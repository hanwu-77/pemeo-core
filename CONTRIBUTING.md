# Contributing

Project-authored source is distributed under Apache-2.0. Contributions intentionally
submitted for inclusion are expected under the same license, subject to Apache
section 5 and existing third-party terms. Retain attribution and identify copied
material and its license. Only submit content you have the right to contribute.
AI assistance does not establish rights to third-party copied code.

Keep Protocol v0.1 and schema 0.1.0 unchanged unless an explicit versioned design
change is reviewed. Separate original statements, inferences and confirmations.
Describe the problem, scope, tests and evidence limitations. Do not silently
rewrite history, remove failed-run evidence or claim a virtual key is a person.

Run unit and affected integration tests per docs/INSTALL.md. Include regression
coverage for actual failures, not tests that merely mirror implementation.
Use synthetic inputs only. Never submit .env, private keys, passkeys, personal
media, database dumps, browser profiles or raw private logs. Security reports
must use the private route described in SECURITY.md.

Please distinguish install usability feedback from validation of the future
AI-source separation workflow. Machine identity and real-model Assist are not
implemented in this candidate.

## Why we build

**以人为本，向善而行！** · **People first. Guided by good.** ·
**Der Mensch im Mittelpunkt. Das Gute als Kompass.**

Read [our shared purpose](PURPOSE.md). Describe whose needs a change serves,
its foreseeable effects, and how it respects people's choices and privacy.
This guides project collaboration; it adds no license restriction.

## Language review

Read [the language policy](docs/LANGUAGE_POLICY.md). Native-speaker review is welcome for the purpose, brand copy and capability boundaries in docs/i18n/. Keep statements, inference and credential-backed confirmation distinct in every language. Ranking is an estimate, not a statement of cultural importance.
