# Release evidence and decision boundary

This repository distributes an experimental, source-only developer preview. Apache-2.0 applies to project-authored material; third-party code and data retain their own terms. A source archive cannot truthfully encode future publication, CI or repository-setting events in its own immutable bytes.

For each release, maintain a separate record bound to the **exact archive SHA-256** and Git commit. The record should state:

- The public file whitelist and archive integrity/security scan.
- Clean installation, dependency/license inventory and tests on the claimed platforms.
- Hosted CI run identifiers, source commit, environment and any evidence limits.
- The real private vulnerability-reporting route, its enablement and test status.
- Name, attribution and historical contribution decisions, together with their limits.
- The selected public repository, release identifier, owner's publication decision and known limitations.

Historical test or CI results for a different archive are context, not proof for a new archive. Hashes show file correspondence, not process trust, software safety or ownership. Private audit packages, local paths, real authenticator data and personal media are outside the public source whitelist.

The project is not a production identity service. Credential lifecycle and recovery limits are described in [known limitations](docs/KNOWN_LIMITATIONS.md). An independent first-install trial is valuable adoption feedback, not a substitute for technical validation or a claim that the future AI-source separation workflow is implemented.
